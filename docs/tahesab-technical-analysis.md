# تحلیل فنی ته‌حساب

تاریخ بررسی: ۱۵ نوامبر ۲۰۲۶  
مسیر نصب: `C:\SoftDev Tahesab`

این گزارش از بررسی ایستا و فقط‌خواندنی فایل‌های نصب، تنظیمات و پایگاه‌داده‌های محلی تهیه شده است. کد منبع برنامه در دسترس نیست؛ بنابراین موارد معماری و API که در این گزارش آمده‌اند، در جاهایی که مستقیماً قابل مشاهده نیستند، «استنباط فنی» هستند.

## ۱. معماری کلی استنباط‌شده

ته‌حساب یک برنامهٔ دسکتاپ ویندوزی با هستهٔ بومی/کامپایل‌شده است که از چند لایه تشکیل شده:

```text
Tahesab.exe
├─ لایهٔ رابط و عملیات حسابداری
├─ DBSource.SQL / TahesabDB.SQL  ← پایگاه‌دادهٔ اصلی Access با پسوند SQL
├─ TTMS.mdb / TTMS_96.mdb        ← اطلاعات مالیاتی و فرم‌های رسمی
├─ Mconfig.db                    ← تنظیمات گزارش و مدیر سیستم
├─ Report/*.fr3                  ← قالب‌های FastReport
├─ TahesabAgent.exe              ← عامل جانبی/به‌روزرسانی/خدمات کمکی
├─ TaxCollectorApp.exe           ← ماژول مالیاتی
├─ Tahesab_PCPOS.dll             ← اتصال POS
├─ SecurityFunctions.dll         ← توابع امنیت/مجوز
└─ UsbLock.dll                   ← قفل/فعال‌سازی سخت‌افزاری
```

برنامه به‌احتمال زیاد معماری «رومیزی با پایگاه‌دادهٔ محلی» دارد. در فایل‌های موجود، API وب عمومی برای عملیات حسابداری پیدا نشد؛ ارتباط‌های قابل مشاهده بیشتر برای به‌روزرسانی، تبلیغ/راهنما، ایمیل و خدمات جانبی هستند.

## ۵. API و ارتباطات قابل استخراج

API عمومی برای CRUD حسابداری از فایل‌ها استخراج نشد. آدرس‌های قابل مشاهده در `OnlineAd.ini` عبارت‌اند از:

- `http://onlineq.tahesab.ir/LastUpdateVer.html` — بررسی نسخه/ورود آنلاین
- `http://onlineq.tahesab.ir/Tip.php` — نکته‌ها یا پیام‌ها
- `http://onlineq.tahesab.ir/ExpUpgrade.htm` — اطلاعات ارتقا
- `http://onlineq.tahesab.ir/P/Online_New.txt` — محتوای آنلاین

تنظیمات ایمیل نیز وجود دارد:

- SMTP: `mailservice11.irandns.com`
- پورت: `587`
- فرستندهٔ پیکربندی‌شده: `Tahesab@mail.tahesab.ir`

این‌ها بیشتر «سرویس جانبی» هستند و نه API رسمی حسابداری. بخش‌هایی مثل `SU`, `SL`, `FH`, `FP`, `FU`, `FA`, `STM`, `STL`, `RDH`, `RDK` در `DataSecurity.ini` مقادیر کدگذاری‌شده/مجوزی هستند و برای استخراج منطق یا دورزدن مجوز استفاده نشده‌اند.

قالب‌ها با پسوندهای `.fr3` و فایل‌های بدون پسوند در `Data\Report` قرار دارند و نشان می‌دهند برنامه خروجی‌های زیر را پشتیبانی می‌کند:

- گزارش حساب و حساب بانکی
- دفتر روزنامه
- بدهکار/بستانکار

- کارکرد ماهانه
- مالیات
- بارکد و برچسب

- مشتری و جزئیات مشتری
- گزارش‌های کارمزدی و حق‌العملی

## ۷. تنظیمات مهم

`Config.ini` نشان می‌دهد برنامه مسیر نصب، تصویر پس‌زمینه، مسیر آخرین پشتیبان و حالت‌های گزارش را نگه می‌دارد. `User_Info.ini` شامل اطلاعات کاربر/محیط و مسیر پایگاه‌دادهٔ آزمایشی است. `Print_Config.ini` تنظیمات چاپ را نگه می‌دارد. `Gadgets.ini` محل ابزارک‌های داشبورد مانند تراز، قیمت، پشتیبانی و ساعت را ذخیره می‌کند.

## ۸. نتیجه برای ساخت نمونهٔ مشابه

برای بازسازی سالم و مستقل، مدل حداقلی زیر پیشنهاد می‌شود:

```text
Product
├─ name, code, category, unit
├─ metal, karat, weight, stone_weight
├─ labor_rate, profit_rate, tax_rate
└─ stock ledger

Party
├─ customer/supplier/both
├─ name, national_id, economic_id
├─ phone, address, postal_code
└─ gold_balance, cash_balance

Invoice
├─ type: sale/purchase/return
├─ party, date, number, status
├─ lines: product, weight, karat, price, labor, tax, discount
├─ payments and due balance
└─ audit trail
```

معماری پیشنهادی برای نسخهٔ جدید: رابط وب مشترک + برنامهٔ دسکتاپ با SQLite محلی، API امن برای نسخهٔ وب، migration نسخه‌بندی‌شده، پشتیبان‌گیری رمزنگاری‌شده و ثبت کامل تغییرات. کپی‌کردن فایل‌ها یا منطق امنیتی اختصاصی ته‌حساب توصیه نمی‌شود؛ می‌توان قابلیت‌های عمومی حسابداری را مستقل و تمیز پیاده‌سازی کرد.

## ۹. محدودیت‌های این بررسی

- کد منبع در دسترس نیست.
- API داخلی و منطق محاسبات از روی فایل اجرایی به‌صورت قطعی قابل اثبات نیست.
- هیچ فایل اجرایی پشتیبانی از راه دور اجرا نشد.
- هیچ داده‌ای تغییر، حذف، ارسال یا به‌روزرسانی نشد.
- نسخهٔ نصب‌شده از نظر امضای دیجیتال: `Tahesab.exe` و چند DLL اصلی بدون امضا هستند؛ ابزارهای Microsoft/AnyDesk/TeamViewer امضای خودشان را دارند.

## ۱۰. معماری سرویس‌های ابری بر اساس وضعیت سرویس ارائه‌شده

صفحهٔ وضعیت نشان می‌دهد اکوسیستم ته‌حساب فقط به برنامهٔ دسکتاپ و دیتابیس محلی محدود نیست و یک معماری چندلایهٔ ابری/شبکه‌ای دارد:

```text
کاربر / برنامهٔ ویندوز / پیام‌رسان
          │
          ├─ رابط ته‌حساب و AI
          ├─ MCP داخل ایران و خارج از ایران
          ├─ API و پورتال توسعه‌دهندگان
          ├─ پیامک، OTP، تلگرام، بله و تماس تلفنی
          ├─ قیمت آنلاین و Reygiri
          ├─ گزارش، ایمیل و خطایابی
          └─ RustDesk برای پشتیبانی از راه دور
```

### گروه‌های سرویس

- مرکز تماس و CRM: خطوط تلفنی، سرور و بسترهای اصلی/جایگزین ارتباط با مشتری.
- Tahesab.ai: چت، رابط پیام‌رسان‌ها، رابط ویندوز و AI، سرورهای AI و تبدیل صدا به متن.
- MCP: سرویس داخل ایران و مسیرهای جداگانه برای Claude و دسترسی خارج از ایران.
- هویت و پیام‌رسانی: SMS/OTP، تلگرام، بله و تماس تلفنی.
- وب و توسعه‌دهندگان: سایت‌ها، My.Tahesab، پورتال تغییرات، مستندات API، وب‌سرویس تست و آزمون صحت API.
- سرویس‌های داخل برنامه: قفل نرم‌افزاری، به‌روزرسانی، قیمت آنلاین، لینک گزارش، ایمیل و گزارش خطا.
- پشتیبانی راه دور: RustDesk شامل Console/API، TCP، UDP، WebSocket شناسه و WebSocket Relay.
- سامانهٔ انگ طلا: API ریگیری از Reygiri.com / ReyTala.ir.

### نتیجهٔ معماری

بر اساس این صفحه، API ته‌حساب چند سطح دارد: API توسعه‌دهندگان، API تست و آزمون صحت، APIهای داخلی قیمت/قفل/گزارش/آپدیت/خطا، API ریگیری و MCP به‌عنوان لایهٔ ابزارمحور AI. بنابراین نتیجهٔ قبلی باید اصلاح شود: در فایل‌های محلی API عمومی قابل استخراج نبود، اما وضعیت سرویس‌ها وجود پورتال مستندات API و وب‌سرویس تست API را تأیید می‌کند. برای استخراج endpoint، schema درخواست/پاسخ و احراز هویت باید مستندات توسعه‌دهندگان خوانده شود؛ صفحهٔ وضعیت به‌تنهایی قرارداد API را نشان نمی‌دهد.

وجود مسیرهای اصلی و جایگزین برای AI، پیامک، CRM، قیمت آنلاین و سرویس‌های داخلی نشان‌دهندهٔ طراحی Failover است. درصدهای موجود در متن فقط وضعیت تاریخی در زمان `2026-11-15 19:17:03` هستند.
